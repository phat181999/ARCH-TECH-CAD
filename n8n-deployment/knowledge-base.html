🏗️ AutoCard CAD — System Knowledge Base

This document is the complete technical knowledge base for the AutoCard CAD system. It covers the backend REST API, database schema, frontend architecture, drawing element types, and the RAG pipeline. Use this document to answer questions about the system architecture, to generate correct API calls, or to guide the CAD drawing engine.

1. System Overview

AutoCard is a browser-based architectural CAD application. It supports 2D drawing, AI-assisted floor plan generation, real-time collaboration, and a modular block library.

LayerTechnologyDescription
FrontendReact 19 + TypeScript + Vite + ZustandSPA drawing editor, deployed to Cloudflare Pages
BackendGo 1.22 + net/http + GORMREST API + WebSocket server, port 8080
DatabasePostgreSQL (Supabase) + pgvectorStores drawings, users, organizations, RAG vectors (1536-dim)
CacheRedisSession caching and pub/sub for real-time collaboration
AIOpenAI GPT-4o + EmbeddingsFloor plan generation, RAG retrieval, compliance checking
TunnelCloudflare TunnelSecure public exposure of the backend
The frontend dev server runs on port 51530. The backend runs on port 8080. Vite proxies /api/* to the backend automatically in development.

7. AI Floor Plan Format (ArchitecturalPlan)

The AI endpoint (POST /api/ai/generate) and the RAG system return an ArchitecturalPlan JSON object. The CAD engine uses this to render a full architectural floor plan on the canvas.

{
  "units": "mm",
  "footprint": { "widthMeters": 12, "heightMeters": 8 },
  "walls": [
    {
      "id": "wall-1",
      "role": "exterior",
      "x1": 0, "y1": 0, "x2": 12000, "y2": 0,
      "thickness": 200,
      "hostBoundary": null
    }
  ],
  "openings": [
    {
      "id": "door-1",
      "type": "door",
      "hostWallId": "wall-3",
      "x": 3000, "y": 0,
      "width": 900,
      "swing": "left-in",
      "orientation": "south"
    }
  ],
  "rooms": [
    {
      "id": "room-1",
      "name": "Living Room",
      "roomType": "living",
      "boundary": [
        { "x": 0, "y": 0 }, { "x": 6000, "y": 0 },
        { "x": 6000, "y": 5000 }, { "x": 0, "y": 5000 }
      ],
      "labelX": 3000,
      "labelY": 2500
    }
  ],
  "gridAxes": [
    { "id": "grid-A", "name": "A", "orientation": "vertical", "value": 0 },
    { "id": "grid-1", "name": "1", "orientation": "horizontal", "value": 0 }
  ],
  "dimensions": [
    {
      "id": "dim-1",
      "role": "overall-width",
      "x1": 0, "y1": -500,
      "x2": 12000, "y2": -500,
      "label": "12000"
    }

}
Units: All coordinates in the ArchitecturalPlan are in millimeters (mm). A standard bedroom is 3000mm × 3600mm (3m × 3.6m). Wall thickness is typically 150–200mm for exterior walls.

9. RAG Pipeline

The RAG (Retrieval-Augmented Generation) system allows the AI to query the vector database for relevant CAD components, building rules, and historical projects before generating a floor plan.

9.1 Embedding Model

All vectors are generated using OpenAI text-embedding-3-small, producing 1536-dimensional vectors stored in PostgreSQL using the pgvector extension.

9.2 RAG Query Flow

1. User sends prompt to POST /api/rag/query
   Body: { "query": "3-bedroom house with open living area", "top_k": 5 }

2. Backend embeds the query using OpenAI text-embedding-3-small

3. Backend performs cosine similarity search across:
   - knowledge_chunks (document knowledge)
   - cad_components (reusable CAD blocks)
   - building_rules (compliance rules)
   - historical_projects (past similar designs)
   - golden_designs (architect-approved templates)

4. Top-K results returned to frontend/AI agent

5. AI agent uses results as context to generate ArchitecturalPlan JSON

6. Frontend renders the ArchitecturalPlan on the CAD canvas

9.3 Ingesting Data into RAG

// Ingest a knowledge chunk
POST /api/rag/knowledge-chunks
{
  "document_title": "Vietnamese Building Code 2020",
  "section_identifier": "Chapter 5 - Fire Safety",
  "content": "Corridor minimum width for residential buildings is 900mm...",
  "metadata": { "source": "QCVN 06:2021", "page": 42 }
}

// Ingest a CAD component
POST /api/rag/components
{
  "component_name": "Standard Door 900mm",
  "category": "door",
  "svg_representation": "<svg>...</svg>",
  "geometry_data": { "width": 900, "thickness": 50 },
  "tags": ["door", "interior", "standard", "residential"]
}

// Ingest a building rule
POST /api/rag/building-rules
{
  "jurisdiction": "VN",
  "rule_category": "accessibility",
  "target_element": "door",
  "rule_type": "min_width",
  "parameters": { "min_mm": 900 },
  "description": "Minimum clear door width for accessibility",
  "severity": "error"
}
